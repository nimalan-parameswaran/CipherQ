On-device intelligence

Why local AI?

The advantages of running intelligence on hardware you control, alongside practical deployment considerations.

Advantages of local intelligence

  • Data ownership: Your documents, search queries, and embeddings remain entirely on your personal server hardware.
  • Predictable operation: Enjoy uninterrupted access without per-query service fees, subscription tiers, or external rate limits.
  • Offline readiness: Search, explore, and query your indexed documents whenever you need them, even without internet connectivity.
  • Transparent architecture: Inspect the full open-source pipeline, retrieval logic, and local model integration on your system.

Practical hardware considerations

  • Memory allocation: Compact systems like Arduino UNO Q share unified memory between the operating system, storage database, and model runtime.
  • Purpose-built models: Local inference uses efficient, quantized compact models optimized for agile responses on personal hardware.
  • Device throughput: Response times scale naturally with the host processor and hardware capabilities of your chosen device.
  • Hardware stewardship: Physical server uptime, network configuration, and backup schedules remain directly under your management.

Technical disclosure

Security & privacy disclosures

CipherQ is engineered with transparent cryptographic boundaries and verifiable local processing. We do not make misleading marketing claims.

Architectural disclosure

Server-managed vault (Not E2EE / Not Zero-Knowledge)

CipherQ is not end-to-end encrypted or zero-knowledge. The server holds the master key and decrypts authorized files into server memory during downloads and text extraction. Anyone with host system administrator access can inspect key material.

Cryptographic method

Authenticated encryption & key wrapping

Files are encrypted with unique per-file Data Encryption Keys using streaming authenticated encryption (AEAD), wrapped under a protected server master key. Full cryptographic specifications are detailed in our technical security disclosures.

Access & authentication

Password hashing & account isolation

User passwords are protected with modern memory-hard hashing. User sessions use cryptographically secure random tokens, and all document and search operations enforce strict tenant isolation.

Processing location

Local search, embeddings & AI

Search indexing, text embeddings, and language model inference run on the local server host. External telemetry is disabled; document contents and queries are never sent to third-party cloud services.

Network & metadata

Metadata & transport security

The database stores basic file metadata (names, sizes, timestamps). When hosting CipherQ outside localhost, operators must configure HTTPS or a secure VPN to protect session cookies and file transfers over the network.

Threat model

Threat assumptions & boundaries

CipherQ protects your data against remote cloud interception, multi-tenant leakage, and third-party AI training. It does not defend against an attacker with root OS access or physical hardware extraction.

FAQ

Frequently asked questions

Clear answers about CipherQ's architecture and capabilities.

What is CipherQ?
CipherQ is an open-source private cloud storage vault and local AI workspace designed for compact hardware such as Arduino UNO Q and Debian Linux. It allows users to store encrypted files, search document contents, and query their files using on-device language models.
Where are my files stored?
Files are stored directly on your server host in an encrypted vault directory. CipherQ does not upload your files or metadata to third-party cloud storage providers.
How does file encryption work?
Each file is encrypted with an individual Data Encryption Key (DEK) using authenticated streaming encryption. The DEK is wrapped under the server's master key and stored in the database. During download or indexing, the server unwraps the key and decrypts the stream in memory.
Is CipherQ end-to-end encrypted?
No. CipherQ uses a server-managed vault rather than end-to-end encryption (E2EE) or zero-knowledge encryption. The server holds the master key and decrypts document text into memory during file downloads and document indexing for AI processing.
Does the AI assistant send documents to an external service?
No. AI inference, text embeddings, and keyword indexing execute entirely on the local server host. Outbound model requests are restricted strictly to loopback addresses, and third-party telemetry is disabled.
What is the difference between keyword and semantic search?
Keyword search looks for exact terms and phrases with relevance ranking. Semantic search converts text into local mathematical vector embeddings to match concepts, ideas, and synonyms even when different terminology is used.
Which file formats are supported?
For secure vault storage, all file types are supported without restriction. For local AI document indexing and text search, CipherQ currently supports PDF, Plain Text (.txt), Markdown (.md), CSV, and JSON files.
What are the storage and AI query limits?
The Free plan includes 1 GB storage and keyword search. The Premium plan includes 5 GB storage and keyword search. The AI Pro plan includes 5 GB storage, semantic search, and up to 100 on-device AI queries per day.
How do I install and configure CipherQ?
Clone the GitHub repository, install dependencies using uv, generate your server master key using the key manager CLI, and start the service with Uvicorn. Detailed instructions are available in our documentation.
Which features are available now?
Available features include authenticated streaming file encryption, integrity verification on download, keyword search, local semantic vector search, on-device AI document question answering with page citations, and administrative tier management.
Is CipherQ open source?
Yes. CipherQ is open-source software under the MIT license. You can inspect the source code, contribute improvements, or self-host your own instance from our GitHub repository.
How do the paid plans work?
Automated billing and self-service payment gateway workflows are currently in active development. Plan tiering is enforced by backend services and can be configured administratively for preview deployments.
