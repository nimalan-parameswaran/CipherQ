Security & Privacy Disclosures

CipherQ is engineered with honesty, transparent boundaries, and cryptographic rigor. We do not make misleading marketing claims.

1. Server-Managed Vault (Not Zero-Knowledge / E2EE)

In an End-to-End Encrypted (E2EE) zero-knowledge architecture, only the client holds the encryption key, and the server cannot read file contents under any circumstance.

Why CipherQ is different: To enable local AI search, keyword indexing, and streaming file operations without client-side model execution, the CipherQ backend must decrypt document text in volatile RAM. Therefore, CipherQ uses a Server-Managed Vault (Option B):

  • Every file is encrypted at rest using an individual 256-bit Data Encryption Key (DEK).
  • All DEKs are wrapped under a Master Key Encryption Key (KEK) held in a protected key file (`.vault_master.key`, mode `0600`).
  • Anyone with root access to the physical host can theoretically inspect memory or key material. CipherQ protects your data against external networks and unauthorized users, not physical device compromise.

2. Plaintext Memory & eMMC Flash Erasure Limits

We do not claim 100% guaranteed forensic data erasure:

  • Volatile Memory (RAM): Decrypted document buffers are closed and dereferenced (`del`, `gc.collect()`) immediately after chunking. However, in high-level managed runtimes (Python), memory management and OS swap paging mean residual byte fragments cannot be forensically zeroed without OS-level `mlock` primitives.
  • Flash Storage (32GB eMMC): File unlinking (`os.remove`) performs logical filesystem deletion. Due to Flash Translation Layer (FTL) wear-leveling on eMMC, NAND flash cells may physically retain ciphertext traces until overwritten. True defense against flash chip desoldering requires OS-level Full Disk Encryption (LUKS).

3. Local Area Network (LAN) & Transport Encryption

Plain HTTP over a local Wi-Fi or Ethernet network (`http://192.168.x.x:8000`) provides zero transport encryption. Eavesdroppers on the same network can capture session cookies and unencrypted file streams.

Plain HTTP is strictly reserved for single-device localhost development (`http://localhost:8000`). When deploying CipherQ to the Arduino UNO Q for home/office use, an encrypted transport must be configured (such as a local TLS certificate via `mkcert`, private PKI, or a secure private overlay like Tailscale).

4. Vetted Streaming AEAD (No Custom Crypto)

CipherQ strictly forbids ad-hoc or unreviewed encryption schemes. All file encryption utilizes vetted, audited streaming AEAD implementations (Google Tink `StreamingAead` or PyNaCl `secretstream`), providing mathematical guarantees against ciphertext tampering, bit-flipping, chunk reordering, and stream truncation.
